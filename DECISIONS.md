## Арт-дирекшн: «Signal Cosmos»

**Ідея.** Всесвіт — це нейромережа студії.

- Вузли — можливості.
- Лінії — інтеграції.
- Імпульси, що біжать лініями, — дані.

Візуал показує саме те, що студія продає: з'єднання систем в одне ціле.

### Типографіка

Шрифти підключаються через `next/font/google`, файли self-hosted.

| Роль            | Шрифт                         | Деталі                                                                        |
| --------------- | ----------------------------- | ----------------------------------------------------------------------------- |
| Заголовки       | **Unbounded** (variable)      | широкий футуристичний; subsets latin, latin-ext, cyrillic                     |
| Текст           | **Manrope** (variable)        | subsets latin, latin-ext, cyrillic                                            |
| Мікролейбли HUD | **JetBrains Mono** (variable) | лише latin: цифри, індекси, коди. Кириличний текст цим шрифтом не набирається |

Літери ą ę ł ż ź ś ć ń ó та ї є ґ і перевіряються на скріншотах. Запасний шрифт для заголовків — Geologica.

### Мотиви UI

- Тонкі кутові скоби-рамки.
- Лінії-виноски від об'єкта до підпису.
- Ретикл навколо об'єкта у фокусі.
- Розріджена типографіка великими літерами.
- Моно-індекси «01 / 05».
- Скляні панелі. Жодних «карток із тінню».

### Характер руху

Важкий і спокійний.

- Дрейф ледь помітний.
- Польоти камери: power3/expo inOut, 1,4–1,8 с.
- Hover-реакції: 150–200 мс.
- Без пружин і «підстрибувань».
- UI з'являється як fade + 8px + легкий blur за 250 мс.
- Reduced-motion: crossfade 300 мс, без автоповороту і без FOV-punch.

## Рішення

**D01. Версії стеку.**

- Next 16.4, React 19.3, three 0.187, R3F 9.8, drei 10.7, postprocessing 3.2/6.39, next-intl 4.15, Tailwind 4.3, zod 4.6, zustand 5.1, Vitest 5.1.
- **TypeScript 6.0, а не 7.** typescript-eslint 8.x підтримує TS до 6.1.
- **ESLint 9.39, а не 10.** eslint-plugin-react, jsx-a11y і import з eslint-config-next мають peer-залежність `eslint ≤ 9`. npm позначає ESLint 9 як deprecated. Переходимо на 10, щойно eslint-config-next його підтримає.

**D02. Статичний хостинг GitHub Pages.**

- `output: 'export'`, `trailingSlash: true`, `images.unoptimized: true`.
- Без proxy/middleware і без route handlers.
- `/` — статична сторінка з meta refresh, JS-redirect на `/pl/` і canonical на `/pl/`.

**D03. Base path і URL сайту.**

- `NEXT_PUBLIC_BASE_PATH` (нормалізується в `src/lib/base-path.ts`) задає `basePath` і `assetPrefix`.
- `NEXT_PUBLIC_SITE_URL` — повний публічний URL кореня сайту разом із basePath. Workflow бере його з `actions/configure-pages` (`base_url`).
- Якщо змінна не задана, береться `https://<domain>` з `site.config.ts`, коли домен справжній, інакше `http://localhost:3000`.
- Шляхи поза `next/link` будуються через `withBasePath()`.

**D04. CNAME.** При деплої через GitHub Actions файл CNAME не потрібен: GitHub його ігнорує, а домен задається в Settings → Pages. Для сумісності `scripts/postbuild.mjs` усе одно створює `out/CNAME`, якщо задано змінну `PAGES_CNAME`.

**D05. Словники розділені.**

- `messages/<locale>/ui.json` — рядки інтерфейсу.
- `messages/<locale>/content.json` — тексти категорій, послуг і кейсів.

Для next-intl обидва файли зливаються в одне дерево. Повні словники використовуються лише на сервері (`src/i18n/messages.ts`). Клієнт отримує тільки вибрані простори імен через `NextIntlClientProvider` або готові рядки через props.

**D06. Доступ до текстів контенту.** Тексти читаються через `src/lib/content-text.ts`, який валідує їх zod-схемою. Відсутній текст ламає збірку. Типізовані `t()`-ключі використовуються для статичних UI-рядків.

**D07. Слаги.** Англійські й однакові для всіх мов (`/pl/services/web/landing-pages/`), як у брифі.

**D08. URL — єдине джерело правди про стан сцени.**

- `routeToSceneState()` — чиста функція з тестами.
- Zustand зберігає лише перехідний стан: підсвічування, якість, прогрес переходу, вибір конфігуратора.

**D09. Маніфест сцени.** Він збирається на сервері для кожної мови (`buildSceneManifest`) і передається в Canvas як prop. Так у браузер не потрапляють повні словники й чернетки кейсів.

**D10. Шейдери** пишуться як TS-модулі з template strings (`/* glsl */`). Окремі loader-и для Turbopack і Vitest не потрібні.

**D11. Детермінована випадковість** (`src/scene/random.ts`, mulberry32). Процедурна геометрія однакова при кожному візиті, а рендер лишається чистим: правило `react-hooks/purity` забороняє `Math.random()` під час рендеру.

**D12. Видимість кейсів.** Чернетки видно, коли `NODE_ENV !== 'production'` або `SHOW_DRAFTS=true` (`shouldShowDrafts()` у `content/index.ts`). У продакшн-збірці лишаються тільки `published`.

**D13. Мова документації.**

- PROGRESS.md, DECISIONS.md, REPORT.md, CONTENT_REVIEW.md і docs/ пишуться українською, бо їх читає замовник.
- README.md і визначення агентів у `.claude/agents/` — англійською, як код (технічна аудиторія та інструкції моделям).

**D14. Формулювання гендерно-нейтральні** в усіх мовах: без «chciałbym/chciałabym», «зробив/зробила» тощо.

**D15. Зміна мови.** Перевірено qa-reviewer у M1.

- Перемикання мови — це м'яка навігація без перезавантаження документа: оновлюються `lang`, HUD і title.
- Canvas при цьому перемонтовується, бо змінюється сегмент `[locale]`. З'являється новий WebGL-контекст, fade-in повторюється.
- За 20 перемикань ніколи не лишалося більше одного canvas, попереджень про контексти не було.
- Це прийнятно: мову змінюють рідко, а стан сцени відновлюється з URL.

**D16. Навігація між сусідніми планетами** стрілками й свайпом робить `router.replace`, тому «назад» повертає до системи. Клік по планеті робить `push`.

**D17. Git.** Репозиторій новий і без remote, тому коміти йдуть одразу в `main` після кожного блоку. Пуш — коли замовник додасть remote.

**D18. Розширення зон відповідальності агентів.** У таблиці з брифу ці файли не закріплені.

- `ui-engineer` володіє кореневими конфігами (`package.json`, `next.config.ts`, `tsconfig.json`, eslint, prettier, vitest і playwright конфіги), а також `.github/`, `public/`, `README.md`, `content/schema.ts` і `content/index.ts`.
- `ui-engineer` може додавати нові ключі в `messages/*/ui.json` з чернетками трьома мовами. Ключі мають бути однаковими в усіх мовах, а нові ключі він перелічує у звіті. `content-writer` потім вичитує їх.
- `scene-engineer` може змінювати значення візуальної ДНК (`dna`, `planet`) у `content/categories.ts`. Структуру схеми змінює лише `ui-engineer` за погодженням з оркестратором.
- Оркестратор веде `PROGRESS.md`, `DECISIONS.md`, `REPORT.md` і `docs/`.

**D20. Портфоліо — опційний catch-all `portfolio/[[...project]]`.** Під `output: 'export'` Next 16.4 відхиляє порожній `generateStaticParams` («returned an empty array»), а в продакшні опублікованих кейсів немає. Один маршрут віддає список (`project: []`) і сторінки видимих кейсів, тому в `out/` немає ні заглушок, ні чернеток. З `SHOW_DRAFTS=true` з'являються сторінки кейсів.

**D21. Стратегія завантаження шрифтів.** Усі шрифти variable. `subsets` у next/font визначає лише preload, а `@font-face` з `unicode-range` генеруються для всіх subset-ів.

- Preload: Unbounded latin і Manrope latin + latin-ext. Це 3 файли, 88,4 KB замість 7 файлів і 287,6 KB за замовчуванням.
- Unbounded latin-ext і кирилиця обох шрифтів підвантажуються на вимогу.
- JetBrains Mono (latin) без preload.
- Варіант зі статичним накресленням Unbounded 500 зекономив би близько 96 KB для польських заголовків, але бриф вимагає variable. Переглянемо, якщо цього вимагатиме бюджет продуктивності.
- Перевірка покриття: `npm run fonts:report`.

**D22. Обхід бага Next 16.4.6 на Windows.** Під час статичного експорту prefetch-файли сегментів пишуться у вкладені теки (бекслеші від `path.relative`), а клієнт запитує плоскі імена.

- `scripts/postbuild.mjs` «сплющує» ці файли. На Linux (CI) це no-op.
- Обхід прибрати, коли Next виправить `convertSegmentPathToStaticExportFilename`.

**D23. Vitest 5 і мала літера диска.** Коли шлях до репозиторію має малу літеру диска (`d:\`), Vitest 5 падає: завантажуються дві копії раннера. Обгортка `scripts/vitest.mjs` нормалізує літеру диска; `npm test` іде через неї.

**D24. next-intl на статичному хостингу.**

- `localeCookie: false`, бо cookie ніхто не читає.
- `timeZone: 'Europe/Warsaw'`, щоб форматування на сервері (під час збірки) і в клієнті збігалося.

**D25. Ідентифікатори підсвічування** (`category:<id>`, `service:<cat>/<slug>`, `portfolio`, `configurator`, `project:<slug>`) живуть у `src/scene/node-ids.ts`. Цей модуль не імпортує three.js, тож UI використовує його без збільшення бандла.

**D26. Огляд всесвіту на телефоні.** Оновлено після D28.

- Напрям огляду вибирається за пропорціями вільної області (`safeRect`), а не всього в'юпорта.
- На головній на телефоні вільна смуга над hero ширша, ніж висока. Тому в кадрі всі 7 вузлів, разом із портфоліо, і розмір вузлів від цього не страждає.
- Портретний огляд без портфоліо лишається лише для високих кадрів (`safeRect = null`).

**D27. Контракт клавіатури й кліків між UI і сценою.**

- UI, що «споживає» Esc (меню), викликає `preventDefault()`. Обробники Esc і «назад» у сцені ігнорують події з `defaultPrevented`.
- Навігація з вузлів сцени спрацьовує на `click`, а не на `pointerup`, бо закриття меню поглинає наступний `click`.

**D28. Контракт `safeRect` між UI і камерою.**

- UI-шар публікує в `src/store/scene.ts` прямокутник в'юпорта, не закритий HTML-оверлеями поточного маршруту: HUD, hero, панель, bottom sheet. Значення в CSS px.
- Камера кадрує фокус усередині цього прямокутника (зсув головної точки, підгонка під менший бік).
- Зміни `safeRect` згладжуються, при reduced-motion застосовуються одразу.
- Причина: у M1 рецензенти виявили, що вузли й системи опиняються під hero, панеллю або sheet (QA M1-03, visual V-01 і V-02).
- Реалізація:
  - `camera.setViewOffset` переносить головну точку в центр rect, а дистанція підганяється під його розміри (`camera/goals.ts`, чисті функції з тестами);
  - зміни перших 0,5 с (fade-in) застосовуються одразу;
  - на телефонах UI не публікує проміжний `null` між маршрутами;
  - у M2 CameraControls `fitToSphere` не використовуємо, бо він ігнорує view offset; лишається власний fit.
- Ціна: на desktop-головній вузли приблизно вдвічі менші, бо вільна область становить близько половини екрана. У M2 можна повернути до 14 %.

**D30. Попередження THREE.Clock.** Його виводить R3F 9.8.2: він створює `THREE.Clock`, який three 0.187 позначає як deprecated. Наш код тут ні до чого, а 9.8.2 — остання версія 9.x.

- Фільтруємо рівно одне повідомлення через офіційний хук three `setConsoleFunction` (`src/scene/three-console.ts`). `console` не патчиться.
- Фільтр прибрати, коли вийде R3F з `THREE.Timer`.

**D31. Межа кількості категорій.** У всесвіті може бути до 30 категорій (`MAX_CATEGORY_NODES`). Якщо їх більше, у dev збірка падає з помилкою, а в production з'являється `console.error` і відображаються перші 30.

**D32. Помилки сцени.**

- Невдале завантаження чанка сцени → сторінка працює без 3D: `import().catch` рендерить замість сцени порожній компонент. Повторної спроби немає, бо Turbopack кешує відхилений чанк.
- Помилка рендеру → `SceneErrorBoundary` один раз перемонтовує сцену через 1,5 с, а після повторної помилки вимикає 3D.

**D29. Анімації HTML під час переходів.**

- Під час клієнтської навігації панелі з'являються як fade + 8px + blur за 250 мс.
- Hero на головній показується після того, як політ камери пройшов приблизно 60%.
- На першому завантаженні будь-якого маршруту анімацій і затримок немає, щоб не погіршувати LCP.

**D33. Хто публікує `safeRect`.**

- Оверлеї позначаються атрибутом `data-scene-overlay`: HUD, hero, індекс категорій, панель або sheet.
- `SafeAreaPublisher` рахує найбільший вільний прямокутник (`src/lib/safe-rect.ts`, чиста функція з тестами). Оцінка — за тим, наскільки великий бокс 1,5:1 (landscape) або 1:1 (portrait) вміщується в прямокутник. Значення в цілих пікселях.
- Перерахунок на resize, зміну маршруту, зміну розміру оверлея й кінець вхідної анімації. Покадрового оновлення немає.
- Тимчасові оверлеї (меню «Послуги», мобільне меню) свідомо не враховуються.
- З `?debug=1` прямокутник видно в `window.__safeRect`.

**D34. Тексти `global-error.tsx`.** Цей компонент потрапляє в базовий чанк кожної сторінки, тому словники він не імпортує. Простір імен `error` з усіх `ui.json` вбудовується під час збірки через `env.GLOBAL_ERROR_TEXTS` у `next.config.ts`, це близько 1 KB. Мова визначається за шляхом.

**D35. Типографіка.**

- Тексти контенту (один раз на мову), а також UI-заголовки й ліди обробляються `bindShortWords`: після однолітерних слів у pl і uk ставиться нерозривний пробіл.
- У словниках NBSP вручну не ставимо.
- У M4 генератор Telegram-повідомлення має замінювати U+00A0 на звичайний пробіл, щоб не роздувати бюджет URL.

**D36. Кольори.**

- Кольори категорій беруться лише з ДНК у `content/categories.ts`; токени категорій із CSS прибрано.
- Бренд-акцент UI — окремий токен `--color-brand`, плюс `--color-nebula` для фону.
- Колір портфоліо має одне джерело: `PALETTE.portfolio` у `src/scene/config.ts`.

**D37. Дублікати 404 у збірці.** Postbuild видаляє `out/404/` і `out/_not-found/`, бо GitHub Pages віддавав би їх зі статусом 200. Для невідомих шляхів лишається єдиний `404.html`.

**D38. Апостроф в українських текстах — `’` (U+2019).**

- Він типографічно правильний і гарантовано є в Manrope та Unbounded. Символ `ʼ` (U+02BC) у шрифтах не гарантований.
- ASCII-апостроф `'` в ICU-синтаксисі next-intl слугує escape-символом і перед `{`/`}` ламає повідомлення.

**D39. `AGENTS.md` від Next 16.** Цей блок правил для AI-агентів генерує `next dev`: він відсилає до документації в `node_modules/next/dist/docs/`. Файл закомічено. Next сам радить так робити: інакше `next dev` щоразу відтворює незакомічену зміну, а вміст корисний для агентів, які працюють із Next 16.

**D40. Панелі на телефонах у landscape.**
- Нижній sheet на 60 % висоти лишає на коротких в'юпортах лише близько 22 % вільної висоти.
- Рішення: коли висота не більша за 30rem, а ширина не менша за ~34rem, використовуємо бічну панель. Bottom sheet лишається для портретних телефонів (вимога брифу).
- Реалізація в M6.

**D41. Варіанти для коротких в'юпортів.**
- Tailwind-варіанти `short:` (висота до 30rem) і `shorter:` (до 22,5rem).
- На коротких в'юпортах hero компактний, ліворуч; категорії в один рядок; hero обмежений висотою під HUD.
- При висоті до 22,5rem HUD стає 48 px.

**D19. Debug-хук сцени.** Якщо в URL є `?debug=1`, сцена публікує `window.__sceneStats`: draw calls, трикутники, програми, геометрії, текстури, час кадру. Через нього рецензенти порівнюють продуктивність у headless-браузері. В інших випадках хук нічого не робить.
